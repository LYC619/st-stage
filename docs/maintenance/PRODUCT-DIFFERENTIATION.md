## API 集成依据

原生 `scripts/extensions/connection-manager/index.js` 仅导出 `init()`；`applyConnectionProfile` 是内部实现，不应直接导入。其公开界面 `#connection_profiles` 按档案 ID 选择并派发 `change`，完成后发出 `CONNECTION_PROFILE_LOADED`，参数为档案名称。`/profile` 命令内部也使用同一条路径，但按名字查找，并支持模糊匹配。

百工选择通过原生下拉框 ID 与事件接入，先校验现存档案及选项，再触发用户选择，避免拼接 slash command 或用名称作为身份。读取原生档案时仅投影 ID、名称、模式和模型摘要，不复制凭据。记录角色推荐时只保存角色头像身份 → 档案 ID；改名仍能关联，删除则显示失效并允许解除。原生扩展不可用时说明原因，保留旧入口。

“已应用档案”与“酒馆允许发送”分别报告：档案加载事件不能证明后端在线，ST 自定义 API 还可能在检查失败后报告“已跳过状态检查”。本轮真实宿主验收确认了这个行为，UI 展示原生状态文本并明确真实模型请求未验证。离开手机页不回滚宿主正在处理的切换；页面不再接收旧回调，重新进入时读取实际宿主状态。点击另一角色不会自动切换后端。

## 原生源码定位

- 表情/立绘：`scripts/extensions/expressions/index.js`。
- 性能设置：`scripts/power-user.js`。
- 变量：`scripts/variables.js`；世界书：`scripts/world-info.js`。
- 连接：`scripts/extensions/connection-manager/index.js`；公开上下文：`scripts/st-context.js`。
- 聊天分支：`scripts/bookmarks.js` 的 `createBranch(mesId, { swipeId })`。
- 交互和文本处理：`scripts/extensions/quick-reply/`、`scripts/extensions/regex/`。
- 聊天备份：`scripts/chat-backups.js`。

## 让用户愿意留下的验证标准

这轮用三个可实际操作的任务衡量：换一张角色卡后无需重配微信；从手机能直接使用原生连接档案且角色推荐不串；关掉渲染或重载聊天后能找到上次分支选择，并且不会覆盖用户已有草稿。手机验收覆盖全 App 的窄屏与短视口；是否更顺手仍需用户集中实测反馈，不能仅凭功能数推断。
