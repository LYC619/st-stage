## 实体手机步骤

1. 记录设备型号、OS、浏览器、输入法、构建号，分别测试竖屏和横屏；记录实际 CSS 视口宽度。
2. 打开手机与微信，使用中文拼音组合输入并按候选词确认；确认不误发送。正常发送后输入框仍可继续输入。
3. 弹出软键盘后检查输入框、发送按钮和最近消息可见；滚动/收起键盘后页面不永久偏移，不产生横向溢出。
4. 从图库打开管理器、图片详情、存储窗口，再逐层关闭；返回正确 App，焦点不落到隐藏内容。支持外接键盘时补 Tab/Shift+Tab/Enter/Escape 路径。
5. 打开角色 A 的微信，发送后立即切换角色 B 和另一个聊天，确认旧回复与状态不会写入新会话；重载后分别保留各自记录。
6. 记录通过/失败及重现步骤；截图只使用合成数据。浏览器设备模拟不能填入实体手机结果列。

## 执行条件

AI 测试需要专用于验收的可用连接；不读取或迁移日常 ST 的 `settings.json`、`secrets.json`。本轮 MVU 使用安装目录中的酒馆助手程序和参考目录中的已识别原始构建，在独立测试用户中加载；使用真实脚本 API/事件，AI 回复继续拦截。助手/MVU 的 CDN 依赖响应哈希保存在结果文件；不宣称完全离线或跨版本兼容。缺少其他验收条件时记录缺失项，继续不依赖该条件的本地工作。
