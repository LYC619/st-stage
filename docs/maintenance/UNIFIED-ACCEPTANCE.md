# 统一实测清单

本轮微信体验版本 **0.9.0+202611052119** 已提交并推送开发仓库与独立扩展仓库，见 [发布记录](history/2026-11-05-publication.md) 和 [G 功能证据](history/2026-11-05-wechat-experience.md)。日常 SillyTavern 安装目录未直接修改。上一轮 A–F 的功能与证据保留，但旧微信的外部数值/钱包/自动跟随主聊天不再是新工作流的验收契约。

## 本轮体验重点

手机首页角色概览移到 App 网格底部并默认折叠。微信从独立会话列表进入；右上角设置可直接编辑称呼与场景，记住通用/联系人专用编辑目标。提示词可见、可改、可恢复，素材可逐组预览和从图库添加；红包接受任意内容及附言。内心想法/当前状态由一次 AI 回复同步更新。

用户主要测试使用体验和操作逻辑；代码、持久化、生命周期、异常和浏览器布局回归由 agent 复核。真实 AI 质量和实体设备体验仍按实际环境记录。

## 实测前准备

使用独立测试用户、合成角色和可丢弃聊天；不要向日常账号注入损坏记录。隔离 runtime 已有最终构建和真实 MVU 测试数据。2026-11-05 用户选择统一实测后，已重启 `http://127.0.0.1:18771/`，打开现有合成角色聊天和百工首页；见 [启动记录](history/2026-11-05-manual-acceptance-start.md)。服务日后停止时，可按以下命令重新启动：

```powershell
# 在开发仓库根目录打开终端
Set-Location test-results/roadmap-2026-11-04/runtime
node --preserve-symlinks server.js --port 18771 --dataRoot 'D:/8.Project/0_0_维护/st-stage/test-results/roadmap-2026-11-04/mvu-data' --browserLaunchEnabled false
```

打开 `http://127.0.0.1:18771`。这里是真实 SillyTavern 1.18.0、酒馆助手 4.11.3 与 MVU `74f930e`，不是日常用户目录。2026-11-05 本轮已保留原测试数据、更新扩展并重启服务，页面实际版本/哈希已核对。微信现存连接可能是自动测试的占位连接，手工 AI 实测前须在测试用户中配置专用可用连接。程序依赖通过 junction 复用，启动时保留 `--preserve-symlinks`；结束后 Ctrl+C。实体手机须使用可安全访问的测试部署，回环 URL 本身只能在这台电脑上打开。

## 一轮功能复核

| 操作 | 预期结果 |
| --- | --- |
| 手机首页查看角色概览，展开后返回首页、刷新 | 位于 App 网格之后；默认折叠，展开偏好保留，后台刷新不改变展开状态 |
| 从角色卡 A 进入微信，返回首页再次进入；再从角色卡 B 进入 | 列表自动加入 A/B 的独立会话；重进不重复创建，已有历史/草稿/未读/状态保留；没有选角色时不创建占位会话 |
| 酒馆与 A 聊天，打开微信 → 新会话 → 选择 B | 酒馆仍是 A，微信进入 B。返回后先看到会话列表，旧记录仍在 |
| 在 A 微信发送后立刻切到 B，填写 B 草稿；待 A 回复 | A 回复只写入 A 并标未读；B 草稿与角色状态不变；各自草稿可恢复 |
| 微信右上角设置 → 通用设置 → 修改称呼/场景 → 保存 → 关闭重开 | 常用字段始终可编辑，仍显示通用设置；保存反馈固定在按钮旁 |
| 选择此联系人专用设置并保存，再编辑通用设置 | 专用设置只影响此联系人；编辑通用设置不会暗中删除专用设置。可明确选择“此联系人改用通用设置”再保存 |
| 展开提示词，编辑/预览实际提示词/恢复默认，保存后发送 | 可看到全部默认文字；自定义内容用于下一条请求，恢复默认明确生效 |
| 发送普通消息，再展开角色状态 | 同一条回复更新消息、内心想法和当前状态；无钱包、天数和额外数值评估 |
| 打开表情 → 管理 → 切组预览 → 编辑素材/启停组 → 从图库添加图片 | 表情可见或显示停用原因；预览图片正确。启用后可发送，禁用或移除不破坏已发图片 |
| 红包填写“一杯奶茶”，加附言，再点击发送 | 内容及附言显示在消息里；模型能理解，不自动扣款 |
| 展开模板 → 保存/导出/导入预览/删除 | 模板默认收起；预览只填表单，保存后才生效；成功/失败有反馈，删除需确认 |
| 在原生 API 面板建两个测试档案，百工选角色推荐，再切角色；点击档案切换，随后改名/删除推荐档案 | 保存推荐和换角色不自动切连接；点击才应用原生档案，改名保留关联，删除可解除。已应用/允许发送不代表真实模型请求成功；旧档案入口仍在 |
| 使用 [示例卡片](../RENDERER.md)，展开分支 → 记住选择 → 关闭/重开渲染或刷新 → 换聊天/swipe/编辑原文 | 选择能恢复且正确隔离；预览不推进主剧情。已有草稿不被覆盖，“填入输入框”后仍由用户发送 |
| 手机窄屏/横屏打开九 App，在微信、API 管理、图库、变量设计中滚动并打开软键盘 | 主要操作可达、弹层不偏出视口；输入中的草稿保留。实体设备/OS 输入法仍需亲自执行 |
| 角色 A → 首页 → 绑定图包 → 切换角色 B，再切回 A | 首页显示正确角色/聊天及六项状态，入口能到对应 App；A/B 设置与聊天不串 |
| 新建含两张远程图片的图包，把第二张设为封面，复制分享串并用不同包名导入 | 新包封面仍为第二张，图片顺序仍为原顺序；纯本地图改用 JSON 分享 |
| 渲染一条含比较符号 `x<y+3 且 z>4` 的合法协议；关闭/开启渲染；对加载失败图片点击或按 Enter 重试 | 文本正确显示，关闭后原文恢复；图片交互仍有效。卡片选择填入草稿后由用户发送 |
| 导出选择角色、聊天、联动世界书、预设和正则；读取期间取消，再重试 | 取消不下载且保留选择；重试只下载完整 ZIP。世界书歧义有提示；身份异常须先核对酒馆数据 |
| 导出 ZIP 在可丢弃用户中按类型恢复 | 角色 PNG、聊天 JSONL、世界书、预设、最小设置刷新后仍在；不要把它当作完整账户一键恢复 |
| 管家体检 → 阅读建议 → 应用 → 再测 → 恢复 | 显示逐项实际结果；原设置可按有效记录恢复。损坏记录提示仅在隔离夹具中测，确认只清提示 |
| MVU App 修改数字，取消第二次编辑，新增并删除测试字段，再刷新 | 已保存值保留，取消值未写入，删除字段不再出现；微信保持独立会话状态，不读取或扣改这些变量 |
| 微信设置 → Tab 操作称呼、提示词和 API；打开红包/照片 → Tab、Shift+Tab、Esc；返回会话列表 | 标签能正确识别控件；模态框内焦点循环，关闭回到来源；切换微信会话关闭旧浮层；切换酒馆角色不打断微信操作 |
| 打开“角色表情”，选择“生气”或“疑惑”，等待保存后刷新 | 发送后仍是所选角色表情，不能变成用户同名表情或文字占位；键盘选择后返回表情按钮 |
