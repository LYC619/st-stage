## 用户可见的变化

- **微信**：保留旧全局默认，新增当前角色覆盖和恢复继承。角色使用稳定头像文件名区分，同名不同卡不混用；同卡不同聊天共享场景配置，记录和数值继续按聊天隔离。切换角色重建有效素材、映射与请求管线；A 的在途回复不会阻挡 B 保存配置或写入 B 聊天。
- **模板**：命名保存、预览套用、JSON 导入导出和二次确认删除。最多 30 个，名称 1–60 字，导入最多 64 KB；严格校验字段、URL 和变量路径。模板只含场景配置，不含密钥、记录或数值快照。预览后仍需保存设置才用于会话。
- **API**：首屏复用原生 Connection Manager，按稳定档案 ID 切换，角色推荐只存引用，不自动切连接。名称变更仍可关联，删除有失效提示；禁用/缺失、超时、连点和离开页面有明确行为。旧档案保留折叠入口，不迁移或删除旧凭据。
- **分支**：卡片协议新增可选 `branch`（每张最多 4000 字符），展开查看可能的发展；保存选择、刷新/重开恢复、清除选择与填草稿分开。保存最近 200 个选择，按角色/群组、聊天、消息时间/序号、swipe、内容及块定位；不存正文。编辑、换 swipe 和换聊天不套用旧选择，草稿仍由用户确认发送。

原生 API 的加载事件只证明档案被应用。真实 ST 1.18.0 的自定义 API 即使状态 HTTP 失败，也可能报告“已跳过状态检查”并允许发送。新入口及旧兼容入口统一说明“酒馆允许发送，真实模型请求尚未验证”，展示原生状态文本，不把它当作后端连通证明。微信仍使用自己设置的 Chat Completions 连接。

分支内容来自当前一条回复，不额外增加后台生成，也不改写主聊天。真正的聊天分叉/checkpoint 继续使用原生功能。九个 App 的审计分别给出保留、整合或收敛理由，不用功能数量证明产品价值。

## 手机端实际修复

最初复现了旧 API 管理器在 ST 移动端高度为零，随后发现弹窗左偏 9px。宿主根节点有 `transform`，原生导航的少量横向溢出会使根页面滚动，固定层因此跟着偏移。`core/fixed-viewport.ts` 用不可见定位探针测量固定坐标原点，同时处理 visualViewport 尺寸与偏移。手机壳、API/图库/变量设计弹窗共同使用，监听文档滚动、视口缩放和平移，关闭时清理订阅；不修改宿主全局样式。

旧 API 管理器补齐模态焦点进入/循环、Escape、返回焦点和列表键盘编辑。真实隔离 ST 的 touch 上下文覆盖 320×667、360×740、390×844、412×915、740×360、320×360，九个 App 与表单滚动保存通过；额外检查短视口保留草稿、合成可视区偏移、三个管理弹窗及宿主横向滚动。共 **136 项布局断言**，这仍不是实体手机/OS 输入法证据。

网页 E2E 的最小 ST 夹具漏了原生 `.mes_text { overflow-wrap: anywhere }` 和盒模型规则，原始 JSON 曾撑到 868px，触发浏览器自动平移与点击命中失败。诊断保存了坐标与截图，补回真实宿主规则后，原始间歇失败路径连续三次通过；点击断言未放宽。Playwright 输出改为独立子目录，避免默认清理影响隔离数据和候选；可通过 `PLAYWRIGHT_CHANNEL=msedge` 使用已安装的浏览器。
