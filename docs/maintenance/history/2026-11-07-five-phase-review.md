## 待修复问题

### R1 / P2：群聊同一轮混用新旧连接配置

位置：`st-extension/src/apps/wechat/replies.ts:57–61`。每位成员的管线在前一位回复之后从实时 `data.config` 创建。A、B 群聊发送后挂起 A，保存新 URL/Key/提示词，再放行 A，B 就使用新配置。本次内存构建复现得到同轮 `old.example.test / OLD PROMPT` 与 `new.example.test / NEW PROMPT`。这违反发送时快照约定，后续成员的上下文可能被发往刚修改的端点。

建议：在第一次等待前快照全轮连接、角色配置和所需管线；新增等待期间保存设置的回归。

### R2 / P2：朋友圈取到其他成员活动抬高时间戳的旧状态

位置：`st-extension/src/apps/wechat/moments.ts:5–8`。按会话 `updatedAt` 选择成员状态不能代表该成员状态的新旧。B 有旧群状态、新私聊状态后，仅 @A 更新群聊时间，会让 B 的朋友圈回退到旧群状态。复现由 `B newer direct` 变为 `B old group`，B 自己没有更新状态。

建议：保存并比较角色状态自己的更新时间，或使用统一的每联系人状态记录；覆盖定向群回复与私聊交错。

### R3 / P2：提及解析误唤醒或漏选成员

位置：`st-extension/src/apps/wechat/groups.ts:36–37`。`includes('@all')` 把 `@allison hi` 识别为全群；存在显式身份 token 时又完全忽略手写名字。A/allison 群中，`@[avatar:allison.png] @A hi` 只选择 allison。

建议：全体提及使用完整 token 边界；稳定身份与名字匹配取并集、按身份去重。增加名字前缀和混合提及测试。

### R4 / P2：宿主没有可用声音时仍报告 TTS 成功交接

位置：`st-extension/src/apps/wechat/bridge.ts:478–479` 与 `voice.ts:15–18`。适配器把 speak 回调正常返回视为可播放。实际 ST 1.18.0 的 `onNarrateText` 在声音禁用或映射缺失时仅提示并返回，外层 speak 回调仍返回空字符串；音频队列异步错误也不是该回调的拒绝结果。

本次执行保留的真实宿主 `onNarrateText` 函数体，控制声音表为空：队列新增 0，微信仍提示“已交给酒馆 TTS 播放。”，转写保持隐藏。这是宿主契约问题，不能只依赖“回调被调用”测试证明失败回退。

建议：检查可用声音/明确交接结果；无法从接口确认时保持转写可读且不将正常返回等同于成功播放。保留供应商异步失败的验证边界。

### R5 / P2：新回复使语音转写折叠并丢失键盘焦点

位置：`st-extension/src/apps/wechat/wechat-app.ts:166–174`。消息区域整体重建，每次 `voiceBubble` 都初始化为收起，仅图片控件有焦点恢复。完整挂载复现：等待回复时展开旧语音并聚焦“收起文字”，新回复到达后，旧按钮脱离文档，焦点变为 BODY，转写重新隐藏。

建议：按消息稳定身份保留语音展开状态、播放状态与活动控件焦点，避免全量 DOM 替换破坏进行中的操作。

### R6 / P2：JSZip 分块加载期间取消导出不能及时恢复操作

位置：`st-extension/src/apps/cloud-export/zip.ts:79–80`。首次加载 `import('jszip')` 时仅在等待前后检查 signal，等待过程不能取消。受控模块加载复现：signal 已取消，但 download promise 在分块到达前仍 pending。调用方的 finally 因此不能清除 busy，用户无法重新选择或重试。现有浏览器取消测试阻塞的是素材读取阶段，没有覆盖分块加载。

建议：将等待模块加载与 AbortSignal 竞争；取消后释放调用方、忽略迟到加载结果，新增首次分块响应挂起测试。

### R7 / P2：CI 无法拦截漏提交的新动态分块

位置：`.github/workflows/ci.yml:80`，必需文件清单位于 55–62 行。提交新主包但遗漏其 chunk 后，CI 构建会在工作区补出 chunk，哈希校验通过，末尾 `git diff --exit-code` 却忽略未跟踪文件。

临时 Git 仓库复现：根目录/预览/分发均有未跟踪分块，parity 通过，末尾 diff 仍退出 0。下载实际提交的用户缺少模块，可能导致整个入口或首次导出加载失败。

建议：校验运行时模块图中的所有产物均受 Git 跟踪，并检查构建后新增/未跟踪产物；新增漏提交 chunk 的 CI 回归。
