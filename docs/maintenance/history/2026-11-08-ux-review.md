# 2026-11-08 前端体验审查与优化（Claude Code）

基线：HEAD `0bf8ae2` + 微信社交记忆批次的未提交工作区（快照 `test-results/ux-review-2026-11-08/baseline-worktree.patch`）。
本轮在其上继续改动，**未提交、未推送、未同步安装仓库**。候选版本 `0.9.0+202611081207`，取代 `0.9.0+202611080043`；正式发布仍为 `0.9.0+202611071934`。

## 主要发现

1. **返回语义不一致**：状态栏「‹」和 Esc 一律回主屏，从微信聊天详情返回会直接退出 App，丢掉列表上下文。
2. **外部设置变更会重挂载打开中的 App**：任何 `updateSettings`（含悬浮窗、设置面板）都会重绘，微信草稿、在途请求、导出勾选会被打断。同一 App 重挂载前也未必先 unmount，订阅和定时器有泄漏风险。
3. **手机高度在高屏上被锁在 580px**，聊天类 App 被压成矮条。
4. **微信信息层级**：「演示模式」和错误信息混在一起，没有就地修复入口；输入中、取消、重试、@ 散成几行；新消息到达时会把正在阅读历史的用户拉到底部，或者在底部出现提示行时把最新消息挡住；会话列表没有时间，群聊预览看不出是谁说的；设置页里「AI 连接」被埋在最后。
5. **群聊一轮共用一个超时窗口**，成员越多后面的成员越容易超时；每个成员都会重新读一遍世界书。
6. **立绘管理/图库**：图床不可达时露出浏览器破图标和 alt 原文；从包详情返回列表时滚动位置丢失，操作结果提示随重绘消失；图库托管说明占了半屏。
7. **导出**：「清空当前分类」只清了角色和聊天，**关联世界书仍保持选中**（真实选择 bug）；全选/反选/清空竖排占掉三分之一屏；当前分类的选中态没有任何样式。

## 改动

- **壳层**（`core/phone-registry.ts`, `core/phone-shell.ts`）：新增可选 `PhoneApp.back(): boolean`，「‹」/Esc 先让 App 内部后退一级，到顶层再回主屏；圆形 Home 键仍直接回主屏。新增 `refreshApp(appId)`，只有提交设置的 App 自己重绘（`st-extension/src/index.ts`）；显隐未变化时不重绘。`unmountActive()` 保证重挂载前完整卸载。手机高度按 2:1 跟随宽度（下限 580）。收起/隐藏时不再读取主屏摘要。
- **微信**：通知条区分「本地演示模式」与错误，附「连接 AI」按钮直达并聚焦 Key 输入框；设置页「AI 连接」置顶并显示实时摘要。聊天状态合并为一行（输入中/进度 + 取消/重试 + @）。阅读历史时新回复不跳转，出现「回到最新」浮钮；贴底时底部 UI 变高也保持贴底（ResizeObserver）。会话列表增加时间，群聊预览带发言人（新模块 `list-format.ts`）。群头像拼图在列表和通讯录共用。朋友圈卡片改成头像列 + 正文 + 页脚的布局。群聊每个成员独立超时窗口，显示「A 正在输入…（1/2）」；世界书每轮只读一次（`memory.ts` 并行读取 + 轮内缓存）。`back()` 逐级关闭表情抽屉、+ 菜单、聊天。空会话显示提示（对比度修到 AA）。
- **立绘管理**：共享 `thumbnail()`，加载失败时换成同尺寸占位（三处图墙都用它）；列表 ↔ 包详情记住滚动位置；重绘后保留状态栏提示。
- **图库**：托管设置改成可记忆的折叠区，说明文字收进 ⓘ。
- **导出**：清空时对每个角色走与取消勾选相同的释放路径，连带释放世界书；批量按钮改为一行三格；补上当前分类的选中样式。
- **验收脚本**：`verify-wechat-{evolution,experience,ux,ux-phase2}` 的会话定位限定为 `direct:`（群聊预览现在会带成员名，按名字匹配会撞到两行）；群头像计数限定在会话列表内。

## 遗留与建议

- 打开微信设置在 jsdom 里要 0.3s 以上，几项设置相关单测在 2–3s，机器繁忙时会撞上 5s 超时（本轮出现过一次，空闲重跑全过）。建议给设置面板做惰性渲染，或者把这些用例的超时单独调高。
- 修复或淘汰上面三个过期/依赖环境的浏览器脚本。
- 真实模型、语音、实体设备、完整读屏仍需对应环境验证；图库瀑布流、@ 内联推荐、拖拽调宽继续暂缓。
