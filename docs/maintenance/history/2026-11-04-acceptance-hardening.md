## 实际修复

- 微信的心情/兴趣滑块、位置和 API 字段有可见关联标签；固定浅色表单显式设置文字颜色，避免继承酒馆深色主题的浅色文字。发送、状态、红包和设置底部的已检出对比度问题修复。
- 状态按钮、图库卡片和启用包按钮的可访问名称包含可见内容。卡片动作说明保留在提示中，角色分组和批量卡片沿用内容名称；没有隐藏可见信息来绕过检查。
- 红包与照片加入具名对话框、初始焦点、Tab 循环、Escape 和返回焦点。照片可用 Enter/空格打开，同会话状态刷新重建消息后仍能返回相应照片；卸载清理焦点监听。
- 表情抽屉有展开状态、键盘进入与 Escape；选择后回到表情按钮。切换聊天同步关闭旧设置、红包、照片和抽屉，防止旧浮层留在新会话。
- 选择角色表情原本按用户素材表解释：同名 ID 会变图，独有 ID 变成文字占位。消息现在保存可选的 `emojiSource`，显示、持久化重开、当前提示词和 RAG 都使用所选素材组；旧记录继续按发送者解释。

新增 `st-extension/src/apps/wechat/accessibility.test.ts` 的 12 项回归保护键盘生命周期、会话切换、卸载、素材身份、保存重开及模型/RAG 含义。原键盘失败与表情失败均先复现，再修复；样式与标签由真实宿主 axe 前后报告验证。

## 自动无障碍扫描与实际键盘

新增 `scripts/verify-accessibility-browser.mjs` 和开发依赖 `@axe-core/playwright` 4.14.0，仅扫描扩展 DOM，运行 WCAG 2.0/2.1 A/AA 与 2.2 AA 标签的适用规则。仅接受明确 `--isolated-data` 的回环宿主；校验浏览器读取的版本和 bundle 哈希。测试使用合成设置、内置表情和占位照片，外部图片请求被拦截，不使用日常用户资料。

**桌面英文 1365×900、中文模拟 320×667，各 19 个界面，共 38 次扫描通过，检出违规 0。** 覆盖首页、9 个 App、微信设置/场景/底部、两组表情、红包、照片、图库管理与变量设计器。每组另有 5 条真实键盘/保存重载断言，检查模态进入/循环/返回、两组表情可达、所选角色表情刷新后保留及照片 Enter/空格。

自动扫描仍有 **74 次 incomplete 规则记录**（两组各 37，含同一控件在多屏重复）：渐变或无法确定的对比度、纯符号按钮名称、空输入值，以及按需创建的弹层 `aria-controls` 引用。这些保留完整目标和原因供人工复核，不计作自动通过，更不是完整 WCAG AA 声明。

已检查窄屏微信、设置顶部/底部、红包以及桌面英文图库截图。合成照片是极小占位图；外部图包图片未联网加载，截图不证明真实素材服务可用。
