# 卡片分支与选择恢复

启用「渲染」中的卡片选择模式后，AI 可返回 2–8 个选项。旧卡片仍可使用，每张卡的 `action` 是准备发送的行动文字。

- 「预览可能的分支」展开可选的剧情片段。它是可能的发展，不会改写酒馆主聊天。
- 「记住此选择」保存选择，关闭渲染、离开聊天或刷新后可恢复；不会填写或发送消息。
- 「填入输入框」只写入 `action`，需自行确认发送。已有或被手动修改的草稿不会被覆盖。
- 「清除记住的选择」只清选择记录，保留输入框和聊天历史。

选择按角色/群组、聊天、消息时间与序号、swipe、消息内容和块位置隔离。消息被编辑、换 swipe 或换聊天后不会套用旧选择。最近 200 个选择保存在当前用户的扩展设置中，仅保存定位信息和卡片 ID，不复制聊天正文；超出上限淘汰最早记录。没有可稳定定位的消息时只在当前打开期间记住，界面会提示。恢复选择不会自动恢复草稿。

作者协议延用 `version: 1`，新增可选 `branch` 字符串，每张最多 4000 字符；`action` 最多 2000 字符。整个 JSON 仍受 64 KB、卡片数量、唯一 ID 和无 HTML 的校验。可写换行，但不要把分支内容写成已经发生的剧情。分支由这一条 AI 回复提供，不额外触发后台模型调用。

```text
<STStageRender>{"version":1,"mode":"cards","title":"下一步","cards":[{"id":"road","title":"沿路调查","description":"寻找山路上的灯光","action":"我选择沿路调查。","branch":"可能的发展：你走向灯光，发现巡逻者留下的路标。"},{"id":"camp","title":"返回营地","description":"与伙伴商量","action":"我选择返回营地。","branch":"可能的发展：你回到营地，伙伴递来一份新的地图。"}]}</STStageRender>
```

若要复制主聊天并沿另一条故事线继续，使用 SillyTavern 原生分支/checkpoint。百工的卡片预览和选择记录不创建另一棵主聊天树。
