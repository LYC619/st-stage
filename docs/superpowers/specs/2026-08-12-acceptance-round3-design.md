# 第三轮真实 ST 验收修复设计

## 状态与范围

- 日期：2026-08-12
- 基线：`origin/main` 的第二轮验收版本 `0.9.0+202608101952`
- 本文记录第三轮真实 SillyTavern 验收暴露的问题及已确认方案。
- 管家 2.0 继续以 `2026-08-11-butler-performance-2-design.md` 为设计基线，在本批修复完成后实现，并与本文新增项目一起进入下一轮真实 ST 验收。
- API 管理按维护者已完成的 OpenAI 兼容渠道实测视为本轮基本通过，不扩大供应商范围。

本批目标不是重做立绘、变量或 Renderer，而是修复真实 ST 生命周期和旧数据迁移中自动化模拟未覆盖的差异，同时把图库的云端预设与本地资源统一成一个可理解的数据模型。

## 已确认根因

### 消息编辑后渲染失效

SillyTavern 1.18.0 在保存或取消消息编辑后会重建 `.mes_text`，随后发出 `MESSAGE_UPDATED`。现有后处理只监听 `CHARACTER_MESSAGE_RENDERED` 和 `USER_MESSAGE_RENDERED`，因此 ST 重建 DOM 后，立绘后处理与 Renderer 都不会重新挂载。

### 关闭隐藏标签后仍看不到标签

现有逻辑把“楼层立绘替换”与“隐藏原标签”耦合：`inline` 或 `both` 模式会无条件用图片替换 `[立绘:...]`，即使隐藏开关已经关闭。该行为与界面上的独立开关含义不一致。

### `<UpdateVariable>` 隐藏失败

现有实现只在渲染后的 `textContent` 中寻找字面量 `<UpdateVariable>...</UpdateVariable>`。真实 ST 会经过 Markdown 和 DOMPurify；未列入白名单的协议标签可能被移除而保留块内文字，导致可见 DOM 已经没有标签边界，后处理无法识别该段内容。

### Renderer 注入成功但不渲染

实测回复包含一个通过 Gal schema 的 JSON 对象，但模型漏掉了 `<STStageRender>` 包装标签。现有解析器只识别包装块，因此按设计回退为普通文本。这不是注入失败，而是模型协议遵从不完整。

### 图库未折叠与预设重复

- `galleryFoldByRole` 的旧默认值是 `false`，旧用户升级后不会自动看到已经实现的折叠界面。
- 批量管理模式当前有意强制平铺；截图处于批量模式，因此折叠被关闭。
- 预设“保存本地”会生成新 ID 和“（本地）”副本，造成云端预设与本地副本同时出现在图库。

### 旧 Prompt 没有自动精简

旧版本的内置底稿使用“表情”等旧措辞。新版只把当前 `BUILTIN_TEMPLATE` 识别为内置模板，旧底稿因此被误判为用户自定义模板，绕过了自动精简。重新点击“填入内置底稿”后恢复精简，证明图包数据本身无须更换。

## 设计决策

### 1. 消息生命周期与可逆显示

后处理事件集合增加 `MESSAGE_UPDATED`，并复用现有按 `mesid` 定位的单楼层处理路径。事件触发后统一执行：

1. 重新处理立绘标签、插图和变量块。
2. 把消息交给 Renderer runtime 重新解析和挂载。
3. 重新装饰楼层图片。

`MESSAGE_EDITED` 不作为最终重挂载事件，因为 ST 在该事件之后才清空并重建 `.mes_text`；监听它会处理即将被替换的旧 DOM。

“显示位置”和“隐藏标签”改为真正独立：

- `overlay`：隐藏开启时摘除标签，关闭时保留标签。
- `inline` / `both`：始终插入匹配的楼层立绘；隐藏开启时只显示图片，关闭时保留原标签并在其后插入图片。
- 匹配失败：隐藏开启时摘除标签，关闭时保留原文。

快照恢复仍只改可见 DOM，不修改 ST 的聊天数据。

### 2. 变量块以原始消息为边界

ST 适配层增加只读的按消息 ID 取原始 `chat[messageId].mes` 能力，消息后处理不直接读取完整 ST 全局。

变量块隐藏使用两级策略：

1. 渲染 DOM 仍包含字面标签时，沿用现有精确文本范围删除。
2. 标签已被 ST 清洗时，从原始消息提取唯一完整的 `<UpdateVariable>` 块，移除协议内部已知的 `<Analysis>` 标签，按忽略连续空白的文本映射在可见 DOM 中寻找唯一对应范围；只有唯一命中时才删除。

若原始消息缺失、块未闭合、可见内容出现多处相同候选或无法建立可靠映射，则不隐藏并保留原文。该规则宁可少隐藏，也不删除无法证明属于变量块的剧情正文。

关闭新变量或“隐藏更新块”后，现有快照机制立即恢复原始渲染结构。

### 3. Renderer 严格协议与保守兜底

包装标签继续是主协议。Prompt 增加明确规则：启用模式时必须输出完整 `<STStageRender>{...}</STStageRender>`，禁止只输出裸 JSON；示例保持可由解析器直接验证。

解析器增加裸 JSON 兜底，但必须同时满足：

- 回复中不存在任何 `<STStageRender>` 起止标签；只要出现残缺标签，就沿用现有错误回退。
- 通过字符串感知的括号扫描找到完整 JSON 对象，不使用贪婪正则截取。
- 整条回复恰好只有一个对象通过现有 `version=1` 及 `gal/cards/battle` 严格 schema。
- 两个或以上对象都通过 schema 时拒绝兜底，保留原文。
- JSON 大小、字段白名单、图片 URL 和各模式上限继续使用现有门禁。

兜底成功时只隐藏该 JSON 对象并挂载 Renderer，块外叙事正文原样保留。无效、歧义或挂载失败仍完整显示源文本。

### 4. 预设同 ID 覆盖层

采用“一个逻辑图包、两种资源来源”模型。云端预设保存本地后保持原 ID、原绑定和单张图库卡片，不再创建“（本地）”副本。

设置增加版本化的 `presetOverrides`：

- 普通自定义包继续存入 `packs`。
- 当前代码提供的预设仍是远程清单的权威来源。
- 用户编辑的预设包信息和本地图片路径写入 `presetOverrides`，以预设 ID 和立绘地址匹配。
- 加载时先读取当前代码预设，再叠加覆盖层：包信息采用用户值；匹配立绘优先使用本地 `url`，当前预设的远程地址写入或刷新到 `remoteUrl`。
- 新版预设增加立绘时自动进入同一包；新版移除的预设立绘不继续作为活动清单项。

覆盖层采用以下稳定形状：

```ts
interface PresetPackOverride {
  metadata?: Partial<{
    name: string
    author: string | null
    description: string | null
    roleName: string | null
    outfit: string | null
    promptNote: string | null
    promptNotePlacement: PromptNotePlacement | null
    outfitNotes: Record<string, string>
  }>
  localSprites?: Record<string, string>
  updatedAt?: string
}

interface PluginSettings {
  presetOverrides: Record<string, PresetPackOverride>
}
```

`metadata` 缺少字段表示继续跟随代码预设，字段为 `null` 表示用户明确清空该可选值。`localSprites` 的键是预设立绘原始坐标 `JSON.stringify([group, outfit, tag])`，不使用包级人名或服装，避免用户编辑包信息后本地图片失联；值只能是通过现有本地图片路径门禁的 URL。加载后生成的活动 `Sprite` 使用本地值作为 `url`，当前代码预设 URL 作为 `remoteUrl`。

预设允许编辑以下包信息：包名、作者、描述、人名、服装、图包备注、备注位置和服装备注。预设仍不允许删除整个包、增加/删除/重命名单张立绘，避免覆盖层与未来清单升级产生不可解释冲突。

提供“恢复内置信息”动作，只清除用户对包信息的覆盖，不删除已保存的本地图片，也不切回云端。资源恢复或本地文件删除继续走明确的资源操作，避免一个信息按钮产生破坏性副作用。

若用户已经使用旧版生成了“（本地）”副本，不自动猜测并合并任意自定义包。只有同时满足以下条件才迁移：包名严格等于当前预设名加“（本地）”、包级人名与服装相同、立绘原始坐标集合完全相同、每张 `remoteUrl` 与对应预设 URL 相同，而且同一预设最多只有一个候选。迁移时把本地 `url` 写入覆盖层、把绑定 ID 换回预设 ID并移除该副本；任一条件不满足就保留为自定义包，防止误吞用户数据。

### 5. 资源状态与失败回退

每张立绘的来源继续使用现有字段：

- `url` 为当前显示源；本地化后是 ST 用户图片路径。
- `remoteUrl` 为可分享的云端源。

包卡片右下角显示资源状态：

- 所有立绘都有本地显示源时显示“本地”。
- 所有立绘都有云端源时显示“云端”。
- 两者都有时并列显示。
- 仅部分完成时显示 `本地 N/M` 或 `云端 N/M`，不把半成品标成完整。

本地图片加载失败且存在可信 `remoteUrl` 时，图片展示层可回退到云端源，并显示可重试状态；不会自动改写已保存设置，也不会把回退误报为本地文件仍可用。

### 6. 折叠与批量管理

- 新安装默认开启“同角色图包折叠”。
- 设置版本升级时把旧版本的默认 `false` 一次迁移为 `true`；新版本中用户主动关闭后保持关闭。
- 普通模式按角色显示多层卡片，点击后横向展开，一次只展开一个角色。
- 批量模式继续平铺，便于跨角色拖拽排序和逐包资源操作，但顶部必须明确显示“批量模式”，并提供显眼的“完成”入口。折叠验收必须在普通模式执行。
- 批量勾选框移到不会与左上角“使用中”标记重叠的位置；资源标签固定在右下角，预设标识固定在右上角。

### 7. 旧内置 Prompt 迁移

仓库保存有限、精确的历史内置模板指纹，包括本次实测使用的“表情”版本。构建 Prompt 和设置迁移共用 `isKnownBuiltinTemplate()`：

- 空模板、当前内置模板和已知历史内置模板都走当前自动精简逻辑。
- 加载旧设置时，已知历史模板规范化为当前内置模板或空模板。
- 只要模板与历史常量不完全一致，就视为用户自定义并原样保留。

不使用模糊关键词判断，避免覆盖用户基于旧底稿做过的真实修改。

### 8. 不透明度与悬浮窗入口

“悬浮窗立绘不透明度”改为范围滑块：

- 范围继续使用现有 20% 至 100%。
- 拖动时实时显示百分比并即时更新悬浮窗。
- 为避免高频写设置，输入过程只更新显示与内存，松手或键盘提交时持久化；具体实现复用 App 的设置更新入口，不增加常驻计时器。

悬浮窗右上角新增眼睛图标按钮，点击后展开手机并直接打开“立绘”App。原齿轮继续打开图库管理，关闭按钮继续只隐藏悬浮窗。三个按钮具有独立命中区、标题和 `aria-label`；移动端不依赖 hover 才能看见。

### 9. 地址解析自动验收

使用真实 `getPresetPacks()` 数据增加表驱动测试，覆盖：

- 默认服装的 `[立绘:图名]`。
- `[立绘:服装/图名]`。
- `[立绘:角色/服装/图名]`。
- 精确服装优先于模糊角色匹配。
- 错角色、错服装、错图名和跨包歧义返回空，不渲染其他图片。
- 同 ID 预设本地化后，三种地址仍解析到本地 `url`，分享继续使用 `remoteUrl`。

这部分替代维护者不方便执行的第 15 项手工穷举；真实 ST 只保留每种地址至少一次的冒烟验证。

## 模块边界

- `core/presets.ts`：预设定义、已知预设 ID、覆盖层合并和资源状态纯函数。
- `core/types.ts` / `core/migrate.ts`：设置版本、`presetOverrides` 和旧默认迁移。
- `core/prompt-builder.ts`：历史内置模板识别和当前 Prompt 构建。
- `st-extension/src/st-adapter.ts`：运行时预设与持久化覆盖层的组装、原始消息只读访问。
- `st-extension/src/message-postprocess.ts`：消息事件、可逆标签显示和变量块可见范围处理。
- `st-extension/src/apps/renderer/parser.ts`：包装块解析与唯一裸 JSON 兜底。
- `st-extension/src/sprite-manager.ts`：同包本地化、可编辑预设信息、资源标签和批量布局。
- `st-extension/src/apps/widgets.ts`：可复用范围滑块。
- `st-extension/src/overlay-dom.ts` / `st-extension/src/index.ts`：悬浮窗快捷入口和手机 App 导航接线。

UI 不自行推断预设合并，适配层不拼接卡片文案，解析器不写 DOM。

## 错误处理

- `MESSAGE_UPDATED` 缺失时保持现有渲染事件兼容；不额外轮询 DOM。
- 原始消息读取失败时，变量隐藏仅使用可见字面标签路径。
- 裸 Renderer JSON 有歧义或校验失败时保留全文，不显示半成品 UI。
- 预设本地化逐张提交；失败项保留云端 `url`，成功项可再次补齐，不生成第二个包。
- 覆盖层损坏时忽略非法项并回退当前代码预设，不影响自定义包加载。
- 预设本地文件不可用时展示失败状态并允许云端回退，不静默删除覆盖记录。

## 测试与验证

### 自动化

按测试先行逐项补齐：

1. `MESSAGE_UPDATED` 保存/取消编辑后重挂载，销毁时正确退订。
2. `inline` / `both` 下隐藏开关开关两种标签语义及完整恢复。
3. ST 清洗标签后，依赖原始消息唯一映射隐藏变量块；歧义时不删正文。
4. Renderer 唯一裸 Gal/Cards/Battle JSON 成功、多个合法对象拒绝、括号字符串和残缺标签安全回退。
5. 旧内置 Prompt 精确迁移，自定义变体保留。
6. 预设覆盖层保存、加载、远程地址刷新、新增立绘合并、损坏覆盖回退和旧副本保守迁移。
7. 同包本地化不改 ID/绑定、不增加包数量，并保留 `remoteUrl`。
8. 资源标签完整/部分状态，批量勾选与角标不重叠的 DOM/CSS 约束。
9. 折叠默认迁移、普通模式堆叠和批量模式明确平铺。
10. 滑块键盘/鼠标提交、实时百分比和悬浮窗眼睛按钮打开 `sprites` App。

## 非目标与延期

- 不修改用户真正自定义的 Prompt。
- 不自动合并无法证明来自预设的自定义图包。
- 不在本批更换 imgbb 托管；长期自有托管仍按 `DEFERRED.md` 单独处理。
- 不扩大 API 渠道矩阵。
- 不把管家 Root 启动防火墙、服务端伴侣或 `config.yaml` 写入带入本轮。
- Renderer 快照图片监听和保守 HTML 检测仍按现有延期记录处理，除非本批修改直接触及同一代码且能以独立测试安全关闭。
