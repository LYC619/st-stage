# 稳定立绘寻址设计

日期：2026-07-24  
状态：已被 `docs/superpowers/specs/2026-07-25-semantic-sprite-address-and-large-pack-design.md` supersede；保留为历史方案，不作为当前实现依据

## 背景

当前多包寻址会根据启用集合，在裸包名和 `包名@判别码` 之间切换；规范别名还包含可修改的包名，且判别码通过删除字符生成，不是单射。结果包括历史地址失效、旧裸地址被静默改指向别包，以及不同包再次生成相同地址。

本设计采用“最小安全兼容”策略：不增加设置字段、不迁移持久化结构；无法唯一判断的旧裸地址返回 `null`，绝不猜测或误配。

## 目标

1. 多包 Prompt 中每个候选都携带稳定的包身份，不依赖启用集合或包名。
2. 完整包 ID 的地址编码必须可证明无碰撞，支持任意 JavaScript 字符串 ID。
3. 包改名、启用顺序变化、停用其他包后，已经生成的规范地址仍能解析到原包。
4. 同名包、相同 `roleName`、相同 `sprite.group` 以及它们之间的交叉冲突均不产生跨包误配。
5. 单包地址继续保持现有简写。
6. CRUD 按有效地址工作，且不会把源图片误判为目标冲突。

## 非目标

- 不为历史裸地址持久化别名映射。
- 不修改 `PluginSettings` 版本或数据结构。
- 不保证未发布、未提交的实验格式（四位 `#hash`、旧 `name@filteredId`）永久兼容。
- 不重构与寻址无关的 Web 或手机 UI。

## 规范地址格式

多包模式下，所有候选的人名层使用：

```text
<可读名称>@<类型>=<完整ID编码>
```

类型：

- `r`：语义人名，来源为 `sprite.group` 或 `pack.roleName`。
- `p`：包名兜底；候选没有语义人名时使用。

示例：

```text
鸣人@r=pack_mdy0_000001/微笑
鸣人包@p=pack_mdy0_000001/居家服/微笑
```

上例只展示普通生成 ID 的可读结果；包含特殊字符的 ID 会经过下面的单射编码。

单包模式保持现有行为：

- 无语义人名：`微笑`
- 有语义人名：`鸣人/微笑`
- 有服装：`鸣人/居家服/微笑`

## 完整 ID 编码

编码保留 ASCII 字母、数字、`_`、`-`；其他 UTF-16 code unit 编为：

```text
~hhhh
```

其中 `hhhh` 是固定四位小写十六进制。`~` 本身也必须编码为 `~007e`。空 ID 使用专用值 `~e`；正常数据仍由现有校验拒绝空 ID。

该编码是单射，因为：

1. 原始 `~` 不会直接进入输出；
2. 每个转义固定为一个标记和四位十六进制；
3. 安全字符逐字保留；
4. 不删除 `pack_` 或任何原始信息。

因此 `pack_ab`、`ab`、`pack_a.b`、Unicode ID 和含控制字符 ID 都保持可区分。

## Prompt 地址生成

`flatten()` 为每个候选保留：

- 原始语义人名；
- 包名兜底名称；
- 完整 ID 编码；
- 规范角色 token；
- 有效服装和图名。

当启用包数量大于一时，所有候选均使用规范角色 token，不再根据当前是否检测到冲突而切换格式。由此保证：

- 启用顺序不改变地址；
- 新增或停用其他包不改变现有包的规范地址；
- 同一语义人名出现在多个包时仍由 ID 区分；
- 包名只用于可读显示，不承担身份。

## 地址解析

### 规范地址

当人名层包含 `@` 时：

1. 必须严格符合 `<名称>@<p|r>=<编码ID>`；格式错误直接返回 `null`。
2. 先按编码 ID 精确锁定包，不按包名匹配。
3. `r` 类型还必须按当前语义人名精确锁定候选，用于区分同一包内不同 group。
4. `p` 类型只匹配无语义人名的候选，并忽略可读包名，因此包改名后历史地址仍有效。
5. 指定包未启用时返回 `null`，不得回落到其他包。

### 旧裸地址

不含 `@` 的地址作为单包或历史兼容地址处理：

1. 人名同时对语义人名和裸包名收集候选，不再让某个命名空间无条件覆盖另一个。
2. 服装和图名过滤完成后，仅剩一个候选时才返回图片。
3. 多个候选跨包同样匹配时返回 `null`；同一包内多个分组共享纯图名时，保留旧行为返回该包的首项。
4. 模糊匹配也必须唯一；跨包不能继续采用“第一个命中”的结果。

这保证旧地址可能失效，但绝不会在环境变化后静默显示另一包图片。

## 包内重复有效地址

同一包内的 `有效人名 + 有效服装 + tag` 应唯一：

- `upsertSprite()` 替换该有效地址的第一项，并删除其余历史重复项。
- `setSpriteGroup()` 先识别源项；目标有效地址与源地址相同时，执行字段规范化而不是报“与自己冲突”。
- 目标地址被其他图片占用时仍抛出冲突错误。
- Prompt 枚举对完全相同的最终地址去重，保持首次出现顺序。

## 错误与兼容策略

- 规范 token 格式错误：`null`。
- 规范 ID 对应的包未启用：`null`。
- 旧裸地址存在多解：`null`。
- 同一包内历史上存在多个分组共用纯图名时，按兼容策略取该包首项；带人名或规范 token 的地址仍按对应维度严格解析。
- 唯一的旧裸地址：继续解析。
- 单包纯图名和三级语义地址：保持兼容。
- 不跨包、不跨角色、不跨服装回退。

## 测试要求

实施前先添加失败测试，至少覆盖：

1. 包改名后规范历史地址仍解析。
2. 新增冲突语义包后，旧裸地址返回 `null` 而非改指向新包。
3. `pack_ab`、`ab`、带标点及 Unicode ID 编码互不碰撞。
4. 同名包、相同 `roleName`、相同 `sprite.group` 的多包地址唯一并各归各包。
5. 启用顺序、停用其他包不改变规范地址。
6. 已停用包的规范地址严格返回 `null`。
7. 单包简写保持现有行为。
8. `setSpriteGroup()` 对包级同名人名执行规范化，不发生自身冲突。
9. `upsertSprite()` 清理已有的重复有效地址。
10. 现有服装维度、模糊匹配和 CRUD 测试无回归。
