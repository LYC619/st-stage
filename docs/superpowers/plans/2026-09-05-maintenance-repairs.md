## 2. 推荐设计及取舍

### 图片文件身份

采用**每次写入一个 128-bit 安全随机标识**，例如 `sprite_<32位十六进制>.webp`，存入固定的 ST 用户图片子目录 `sprite_overlay`。图片标签/包名/角色名仍用于 UI，但不再决定物理文件唯一性；旧路径继续可读，不移动或覆盖旧文件。随机源不可用就失败，不用时间戳或 Math.random 降级。

不选“包名/服装/tag 拼接”：这些都是可变、可重名、会被清洗的显示属性。不选“全局内容哈希直接作为持久化文件名”：这会引入跨包共享引用、垃圾回收和覆盖验证协议。**仅在一次迁移/导入任务内对相同 data URI 去重**；不同任务不承诺复用同一磁盘文件。

### 严格保存成功契约

ST 保存成功必须同时满足：POST 成功、响应包含本次新文件的安全本地路径、随后同源读取的内容与提交字节一致。HTTP 413/500、网络中断、超时、无 headers 能力、异常响应和校验失败均抛错，不能返回原 data URI 当作成功。Web 模拟器显式内嵌的行为不改，不能因此放宽 ST 路径检查。

### S1 迁移语义

- **主动入口**：图库中“存储检查与迁移”，启动时不上传、不替换、不清空数据。
- **备份在先**：下载本插件迁移备份，用户确认已保存在本机，才允许上传。备份不是选择式 ST 标准备份；后者并不完整包含本插件状态。
- **分两阶段**：串行上传并验证，先保存在内存暂存结果；用户再确认应用成功项。关闭/取消暂存阶段不改变设置；应用时按最新引用逐项比较，跳过期间已编辑/删除的目标。
- **部分失败**：显式展示成功、失败、冲突、未处理和不支持项；只在用户确认后应用成功项，其他仍保留原图，可重试。
- **JSON 导入**：允许便携文件继续内嵌。安装到 ST 时，所有内嵌图必须先保存成功；任何失败/取消都不安装该包，不将失败图以 base64 混入运行设置。
- **无自动删文件**：取消、校验失败、提交冲突可能留下未引用的新文件，这是避免误删/回滚失效的保守取舍。本批不实现磁盘垃圾回收，也不能把暂存文件称为已清理。
- **不作虚假落盘承诺**：当前 `saveSettingsDebounced(): void` 无服务端写盘确认。应用成功只说明内存和宿主保存队列已更新；须重新打开页面验收。不能把 `await saveSettings()` 当成磁盘事务已完成。
- **不扫写 App 私有数据**：只自动替换有明确 schema 的立绘引用；`apps` 中可能包含提示词、变量或 API 配置，检测到内嵌文本仅统计/提示，原样备份，不递归改写。

### 执行方式

推荐分批实现、分批验证，最后统一验收和发布。相比一次大补丁，更容易定位回归；相比先做全部 UI，更早建立可靠数据边界。若确需先发紧急补丁，仍必须覆盖 R1/R2/R3/R5 和双渠道门禁，且不能宣称 S1 已完成；默认不分两次发布。
