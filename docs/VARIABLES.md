# 变量 App 使用指南（🔢 MVU + 🧮 新变量）

st-stage 手机里有两个变量相关的 App，解决同一件事的两种场景：**看见并管理「AI 在这个故事里维护的状态数值」**（好感度、体力、时间、地点……）。

| | 🔢 **MVU** | 🧮 **新变量** |
| --- | --- | --- |
| 适用 | 角色卡本身是 **MVU 版**（世界书带 `[InitVar]`/`[mvu_update]` 条目 + MVU 脚本） | **任何普通角色卡**，卡里什么都不用带 |
| 前置 | 装了 MVU 框架（或酒馆助手可降级） | 无。不依赖 MVU / 酒馆助手 / 世界书 |
| 变量由谁维护 | 卡片世界书的规则 + MVU 框架 | 你在「变量设计」里定义，st-stage 自己注入与解析 |
| 数据存哪 | MVU 的楼层变量（`stat_data`） | st-stage 自己的逐楼快照（`message.extra`），与 MVU 完全隔离 |

一句话选择：**卡是 MVU 卡就用「MVU」看和改；普通卡想要变量系统就用「新变量」从零起一套。** 两个 App 互不干扰，可以同时装着。

---

## 共用的变量树界面

两个 App 的主界面是同一套「变量树」：

- **折叠分组**：对象按层级折叠展开，展开状态会记住，编辑/自动刷新不会把你点开的层折回去
- **点值编辑**：点任意叶子进入编辑。新变量按定义显示数字框、枚举下拉、布尔开关或文本框，并在保存前校验；MVU 变量按当前值类型显示布尔、JSON 或通用文本控件
- **✕ 删除**：每张卡片右侧，确认后删除
- **＋ 新增变量**：MVU App 底部提供修补入口，点号路径分层（如 `状态.体力`）；新变量请在「变量设计」中新增定义
- **变化徽标**：和上一次有变量的楼层做对比——<span style="color:#7ee2a8">+3</span> 绿涨 / <span style="color:#ff9a9a">-10</span> 红跌 / `改` 非数值变化 / `新` 新增路径
- **自动刷新**：AI 回复导致变量变化时自动更新（正在编辑时不打断，编辑完再刷）

## 🔢 MVU App

给 **MVU 版角色卡**用的变量面板：把当前对话最后一层的 MVU 变量（`stat_data`）拍平成树，支持查看、编辑、删除。

### 你需要知道的

- **数据来源两条通道**：优先走 MVU 框架（`window.Mvu`），MVU 没装或读不到时降级酒馆助手；顶栏会显示当前来源和楼层号。两者都没有（如网页模拟器）时只读。
- **`[值, "描述"]` 二元组**：MVU 变量常带描述（显示为卡片副文本）。编辑值时描述自动保留，不会被抹掉。
- **删除是真删**：直接写回 MVU 数据。删除卡片规则里仍在维护的变量，AI 下一轮可能把它写回来——这是 MVU 卡的正常行为。
- **「新增变量」是修补工具**：MVU 卡的变量由卡片世界书定义、框架维护，手动新增的路径 AI **不会**主动维护。它只用于修补卡片缺失的变量或调试。
- **精准刷新**：监听 MVU 的 `mag_variable_update_ended` 事件，变量真的更新了才刷新，不做无效轮询。

## 🧮 新变量 App

**内置的轻量变量追踪系统**：不依赖 MVU、酒馆助手或世界书条目，给任何角色卡加一套「AI 自动维护的变量」。原理与 MVU 相同（注入规则 → AI 按格式输出 → 解析落库），但定义变量全程 GUI，不用手写世界书。

### 三分钟上手

1. 手机打开 **🧮 新变量** → 点 **「打开变量设计」**
2. 模板库选一套点 **「替换」**（恋爱单角色 / 恋爱多角色 / RPG / 日常陪伴，变量和更新规则都已写好）
3. 回手机页打开 **「启用变量追踪」**
4. 正常聊天。AI 回复末尾会输出变量更新块，st-stage 自动解析并更新变量树

> 多角色模板卡片里先填写两个角色名，再点「替换」或「追加」；所有路径、描述和在场门禁会一起生成，不用导入后逐条改名。

### 手机页（日常使用）

只有三样：**启用开关**（说明在 ⓘ 里）、**打开变量设计**、**变量状态树**。点状态树叶子可按定义类型编辑；类型或枚举不符会留在编辑态提示错误，越界数字按定义范围裁剪。校验通过后写入当前楼快照，并立即生效到下一轮注入。

### 变量设计弹窗（设计与调试）

| 区域 | 说明 |
| --- | --- |
| **模板库** | 内置四套模板一键 **替换 / 追加**（追加跳过重名路径），均含日期、时间、时段及逐变量更新规则；多角色模板可先填写角色名。可把当前定义**存为自定义模板**（换卡复用），自定义模板可删除 |
| **变量定义** | PC 左列表右表单，点谁编辑谁。字段：**路径**（点号分层，如 `角色.小雪.好感度`）、**类型**（数字/文本/布尔/枚举）、**默认值**、**描述**（给 AI 看）、**范围**（数字，越界自动修正）、**枚举选项**、**更新规则**（见下）、**对 AI 隐藏** |
| **生成设置** | 输出格式（JSON Patch 推荐 / `_.set` 老版 MVU 兼容）、注入深度 |
| **注入预览** | 当前实际注入给 AI 的完整文本，改完定义立即可查 |
| **解析日志** | 最近一次 AI 输出的逐条解析结果：✅ 接受 / ⚠️ 已修正（如数值越界被裁剪）/ ❌ 拒绝（补丁格式错误、危险或未定义路径、类型不符、枚举外取值） |

### 更新规则：让变量不乱跳的关键

每个变量可写多行「更新规则」（每行一条，随注入发给 AI），例如好感度：

```
正面互动 +1~3
重大事件（告白、共渡难关）±5~10
无实质互动时保持不变，禁止无缘由跳变
```

类型约束（范围/枚举/「输出完整数值禁止增量」）会自动生成，不用写。**社区实测：规则写得越具体，AI 越守规矩**——内置模板的规则都按这个标准写好了，可以直接参考。

### 工作原理（想了解的话）

- **注入**：按你的定义生成三段式提示词——当前状态 / 逐变量更新规则 / 输出格式（要求 AI 先写简短 `<Analysis>` 分析再输出 JSON Patch 数组）。走独立注入通道，与立绘注入互不影响。
- **解析**：AI 回复到达后提取 `<UpdateVariable>` 块，先逐条校验 JSON Patch 结构，再过 **schema 门禁**。格式错误、危险路径、未定义路径和类型/枚举不符会被拒绝，数值越界自动裁剪到范围；单条错误不会阻断同一块里的后续合法更新。`remove` 只能删除变量设计中精确定义的叶子，不能删除整个分组或未知路径。结果可在解析日志核对。
- **存储**：状态快照**逐楼**存在消息的 `extra` 字段里（随聊天文件持久化）。swipe / 重 roll 自然以上一楼快照为基态，不会串。
- **隔离**：与 MVU 的 `stat_data` 完全分开，两套系统同时存在也不冲突。

### FAQ

- **AI 不输出变量块？** 检查：① 开关是否启用（注入预览非空才会注入）② 模型是否足够听话——JSON Patch 格式对多数模型没问题，个别模型可试切 `_.set` 格式 ③ 楼内看 AI 回复末尾是否真的没有 `<UpdateVariable>`。
- **变量乱跳 / 增长太快？** 给该变量写更新规则，明确幅度与触发条件（参考内置模板的写法）。
- **换了角色卡，定义还在？** 是。变量定义和自定义模板是全局配置；但**状态快照跟着聊天走**，每个对话各自独立。
- **回复里能看到 `<UpdateVariable>` 原文？** 已知现状，隐藏/折叠功能在计划中。
- **删除定义会丢数据吗？** 不会动已保存的楼层快照，只是 AI 不再维护该变量；树上如果还想清掉值，用状态树的 ✕。
